## 输入与权限

```json
{
  "action": "prepare_prompts",
  "roomId": "<room UUID>"
}
```

请求携带有效匿名 Auth JWT。服务端通过当前认证身份找到有效 profile，并检查该 profile 仍绑定当前 auth user、房间未过期、调用者是房间成员、房间仍处于 lobby。房间任一成员均可触发，不限房主；同一房间最多领取一次任务。

客户端不提供题目、方向、模型、提示词、玩家答案或最终候选。请求 ID 按现有公共响应规则生成，不向这个 action 私自新增必填请求字段。

沿用公共错误码：无有效身份使用 `UNAUTHORIZED`；已被替换的身份使用 `IDENTITY_REPLACED`；不存在或非成员房间统一使用 `NOT_FOUND`；房间过期使用 `EXPIRED`；非 lobby 使用 `INVALID_PHASE`；输入非法使用 `INVALID_INPUT`。先验证访问资格，再返回房间阶段或过期信息。

## 执行顺序

### 1. 短事务领取

锁定 room 行，在事务内复核权限和阶段，检查现有 `prompt_generation_state`。

- 尚未领取：原子标记已领取，提交事务，再发起模型请求。
- 已在生成：返回处理中，不调用模型。
- 已结束：返回既有处理状态，不再调用模型，包括之前失败或没有候选的情况。

不得仅用函数实例内的布尔变量去重；两位成员、刷新和多实例并发均需通过同一数据库状态约束。

### 2. 事务外调用 C 的生成实现

随机选两个不同方向，最多一个为不指定。只发送规则、方向、避开词和输出格式，不传人工题库或玩家内容。

使用新版生成规则：每题是一个短设定加一个核心决定，只问一件事；合计尽量不超过 25 个词、最多 180 个 Unicode code points。允许两句，也允许 `Would you? If so, where/who?` 这种表达同一决定的连问。设定可以跨越时代、文化、异能或世界规则，但回答落到“你”，使用平实英文，不要求专业知识，也不限制为日常生活题。

整个模型请求和响应读取最多八秒，关闭 SDK 自动重试。输出为 `{questions:[{text}]}`，检查后得到 0–2 道候选。超时、拒答、结构错误或服务故障直接结束，不发第二次修复或补题请求。

**模型调用期间不能持有房间锁。** `start` 是独立请求，不等待本次生成完成；不要在客户端把开始按钮绑定为“生成完成后才可点击”。

可在当前 `prepare_prompts` 请求内等待这一有界调用；若 B 选择后台执行，必须使用部署平台支持的生命周期机制，不能启动一个无人等待的 Promise 后就假定它一定会完成。

### 3. 短事务写回

执行 3.3 的筛选后，重新锁定同一 room 行，再检查任务归属、房间有效期与阶段。

- 仍为 lobby 且任务可完成：保存合格候选到服务端题池，记录终态。候选 ID 和版本在接受时固定，新候选标记 `question-generation-v2`；不重写旧版本记录。
- 已开局：丢弃本次候选，不改变题目快照、轮次或房间阶段。
- 已过期、被清理或任务已终结：丢弃结果，不重新创建房间或覆盖终态。
- 技术失败：记录失败终态，不保存假题，也不重新领取。

`start` 与本次写回必须锁同一 room。写回先获得锁并成功保存，则 start 可以看到新候选；start 先获得锁并开始游戏，则迟到候选必须丢弃。

函数实例异常退出时也不能让开局依赖悬挂的生成任务。B 应为已领取任务记录可判断失效的时间信息并终结过期状态；终结不意味着重新调用模型。相关数据库字段由 B 在实现时统一确认。

## 返回什么

沿用 `{data, error, requestId}` 公共响应，设置 `Cache-Control: no-store`。仅返回处理状态，不返回模型原文、完整候选池、密钥或提供方错误信息；中间字段不进入 Realtime 广播。

下表描述必须区分的语义，不另行固定尚未实现的枚举或数据库 schema；具体字段由 B 接入共用 contracts 后供 A/C 引用。

| 处理结果 | 客户端含义 | 可否再次生成 |
| --- | --- | --- |
| 正在处理 | 本房间已领取，稍后可读取处理状态 | 否 |
| 完成且有候选 | 已得到可用的新题候选 | 否 |
| 完成但无候选 | 正常结束，没有合格候选 | 否 |
| 技术失败 | 本次生成失败，游戏仍可使用已有题池 | 否 |
| 迟到结果丢弃 | 游戏已经开始，保持既定题目 | 否 |

模型故障是这次生成尝试的终态，不应伪装成正常空结果。若 B 将其映射为公共错误，需先在共享合同中确定错误码，不能套用答案评估失败的含义。认证、输入或数据库故障按真实接口失败处理；写库失败不得报告候选已经保存。

## 与 3.3 的边界

3.2 负责一次有界生成及返回候选；3.3 负责对照人工题库去重、进一步检查不合格内容、混入可用题池和无放回抽三题。

3.3 的本地质量门位于 `_shared/content/prompt-pool.ts`：检查外部结构、英文问句基本形态、空题、长度、重复、私人资料请求、模型指令残留、URL/代码块和生成提示要求避开的高频意象。通过者与39道人工题进入同一数组，再均匀无放回抽三题，不设置“两旧一新”等来源配额。

本地规则只能排除明显不可用内容，不能可靠判断趣味性、开放性、历史知识门槛或是否暗含标准答案；这些仍需3.9真实模型样例与人工审阅。不要因 schema 通过就宣称语义质量已经验收。

C侧纯函数已覆盖候选检查、混池、无放回抽题和已有快照复用。生成失败、没有合格题或来不及时只使用人工题；没有必须包含AI题的配额。B仍需在start事务锁内读取已落库候选、调用选择函数并保存完整三题快照；prepare_prompts写回必须锁同一room并在已开局时丢弃候选。完成这项数据库联调前，3.3不能标为端到端完成。

## 验收场景

- [ ] 未登录、旧身份、非成员、过期房间和非 lobby 请求被正确拒绝。
- [ ] 两位成员同时触发，模型实际只收到一次请求。
- [ ] 刷新或重复请求只读取已有状态，不产生新的模型调用。
- [ ] 生成返回两题、一题、空数组时都能正常结束。
- [ ] 超时、拒答、网络错误和非法输出结束为失败，不触发重试。
- [ ] 请求不包含人工题库、示例题或玩家私人内容。
- [ ] 使用 v2 提示词，允许“短设定＋一个问题”的两句格式；长度按完整题目计算。
- [x] 本地质量门拒绝空题、重复、明显格式错误、私人资料请求和模型输出残留；语义质量留待3.9人工校准。
- [ ] 新候选记录 v2 版本，已有题目快照和历史版本保持不变。
- [ ] 模型尚在处理时仍可 start，且不存在持锁八秒的情况（待B事务实现）。
- [ ] 分别验证“写回先完成”和“start先完成”，既定题目均不会被晚到结果改写（纯函数已验证已有快照复用，数据库锁仍待B）。
- [ ] 实例退出或数据库写入失败不会误报保存成功，也不阻塞开始游戏。
- [ ] 前端响应、订阅和日志均不泄露候选池或服务端凭证。

以上场景需代码与真实集成验证后再勾选；本次文档交付不代表接口已部署或调用验收通过。

## 实现（2026-09-27，待远程验收）

- 数据库：`supabase/migrations/202609270010_prompt_generation.sql` 新增私有表 `room_prompt_pools`（状态 processing / ready / empty / failed / discarded、30 秒租约、0–2 道候选），以及 `claim_prompt_generation`、`finish_prompt_generation` 两个只给 service_role 的函数；二者与 `start_room` 锁同一 room 行；`start_room` 增加默认为 null 的 `p_pool_seen`，在锁内发现候选已在读取后变成 ready 时返回 POOL_CHANGED，由函数重读再抽一次（旧版函数不传该参数，行为不变）。非 lobby 的请求一律 INVALID_PHASE。rooms 上早先预留的 `prompt_candidates_json`、`prompt_generation_state` 没有使用：rooms 在 Realtime 发布里，候选放在那里可能随更新外泄。
- `game` 函数：`prepare_prompts` 先领取，领到的一方在锁外调用 `generatePromptCandidates`（`createOpenAIQuestionGenerator`，low 推理，8 秒上限，不重试），经 `filterGeneratedPrompts` 筛选后写回；其余调用只返回已有状态。`start` 读取 ready 候选后用 `selectGamePrompts`（CSPRNG）抽题；题池读不到时只用人工题开局，不因新题失败挡住开局。响应只含 `{status}`（`PromptGenerationResponseSchema`）。
- 前端：`src/services/game-client.ts` 的 `preparePrompts`；`src/GameApp.tsx` 在快照为 lobby 时调用一次，忽略失败。
- 验证：本地测试覆盖生成请求体（严格结构、low 推理、不含人工题）、失败不重试和响应不含候选；三个 Edge Function 类型检查通过。数据库函数与端到端行为需部署后运行 `npm run verify:prompts`（会产生真实模型调用）。
- 抽题不设来源配额：45 道人工题加 2 道候选时，一局含 AI 新题的概率约 12.5%。
